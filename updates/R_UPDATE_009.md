## C. Why the Update Was Necessary

Without true multi-file recursive composition, hardware-stable local inference, and human-grade visual verification, Mini Hivo's weak-model Swarm thesis remained limited to single-file existence proofs:

1. **Recursive scaling requires compositional contracts:** Splitting a 3-file project across weak-model workers fails whenever children share mutable paths, guess sibling function signatures, or attempt to run downstream test suites that have not yet been authored.
2. **Consumer GPUs exhibit discontinuous KV-cache cliffs:** On 6 GB WDDM hardware, crossing the VRAM boundary silently degrades generation `24.5x` (`98.5 -> 4.0 tok/s`), turning 3-minute runs into 10-minute budget exhaustions while high Epoch-0 temperature (`0.15`) inflates token volume `4.6x`.
3. **Context compaction must never erase the user's specification:** Compacting `messages[1]` ahead of failed `19 KB` tool arguments blinds the worker on the very turn it needs recovery.
4. **Human-ready interactive apps require visual-state integrity:** A game that loads to a blank black canvas before clicking Start, overlaps HUD badges over controls, or fails because `"window"` matched `"win"` undermines both human usability and verifier trustworthiness.

## F. How the Fix Works

1. **Pre-Preflight VRAM Eviction & Hardware-Aware Context Budgeting (`mini.py::main`, `ask_ollama`):**
   Before running `run_host_preflight`, CLI startup queries local Ollama `/api/ps` and sends `keep_alive: 0` to evict stale resident models so `gemma4:e4b` loads into dedicated GPU VRAM (`~98 tok/s` instead of `4.0 tok/s` WDDM CPU spill). Both programmatic `reset_run` and CLI `--decoding-policy` default to `"fixed"` (preserving legacy CLI/preflight and deterministic unit-test expectations), while `--decoding-policy adaptive` enables the adaptive schedule and caps `context_window` at `10,240` whenever `estimate + builder_predict <= 10,240` and `estimate <= 8,192`, giving `6,144`-token greenfield `Builder` drafts full headroom while staying strictly below the `>= 11,264` `+5.95 GB` KV-cache VRAM cliff.
2. **Role-Conditioned & Stagnation-Adaptive Decoding (`hivo/hyperparams.py`, `mini.py::ask_ollama`):**
   `resolve_decoding_options` assigns low-entropy analytical parameters (`T = 0.05, min_p = 0.05, top_p = 0.85`) to structured/planning/review roles, disciplined Epoch-0 synthesis parameters (`T_0 = 0.08, min_p = 0.08, top_p = 0.90`) to `Builder`, and escalating diversity (`T = 0.20..0.48`, `min_p = 0.07..0.16`, `repeat_penalty = 1.06..1.15`, `repeat_last_n = 192`, `seed = seed_base + 7919 * steps`) only when `epoch >= 1`, `stagnant_count >= 1`, or `role == "Repairer"` (or when retrying an empty `<end_of_turn>` response).
3. **Protected Task-Prompt Compaction (`hivo/context.py::compact_messages`):**
   When conversation characters exceed `max_chars`, `compact_messages` marks `projected[1]` (`role == "user"`) as `protected_anchor` and strips oversized historical `tool_calls` argument strings (`> 700` chars -> `""`) across all turns before compacting intermediate prose, ensuring a truncated `19 KB` `write_file` call never erases the task specification.
4. **Assume-Guarantee Disjoint Ownership & Sibling Interface Certificates (`hivo/assume_guarantee.py`, `mini.py`):**
   - When `decide_task_fit` / `decompose_task` splits a multi-file creation goal (`SOURCE_CREATION_MULTI_OWNER_SPLIT`), `partition_disjoint_child_ownership` assigns each target file to exactly one owner child (`owned_mutation_paths`), grants downstream children read-only visibility (`read_only_sibling_paths`), orders producers before consumers via acyclic `depends_on` (`metrics.py` -> `cli.py` -> `test_metrics.py`), and strips deferred test filenames from upstream producer `done_when` clauses.
   - `_impact_candidate_for_worker` enforces `owned_mutation_paths` so Child 1 cannot write `cli.py` or `test_metrics.py`. If an upstream child invokes `run_file`/`run_command` on a not-yet-created sibling test file, `_is_deferred_sibling_test_path` returns `[not_applicable]`, which `verification_routing.py` excludes from test-failure accounting.
   - Once Child 1 commits `metrics.py`, `extract_file_certificate` parses its exact AST function signatures and `format_sibling_guarantees_context` injects `ASSUME-GUARANTEE SIBLING CONTRACT` into Child 2 (`cli.py`) and Child 3 (`test_metrics.py`). During child writes and at `run_integration_preflight`, `verify_compositional_certificates` checks cross-file imports, DOM `#id` selectors, importmaps, and Three.js core-vs-addon symbols; when `0` conflicts exist, `aggregate_task` runs with `mutation_optional=True` so Root verifies the integrated suite without redundant rewrites.
5. **Visual-Execution Pre-Start Render & HUD Anti-Overlap Oracle (`hivo/quality_rubric.py`, `hivo/verification.py`, `mini.py::browser_snapshot`):**
   Before invoking `start()` on `window.AGENT_GAME`, `browser_snapshot` captures a JPEG of the initial `<canvas>` and computes the pixel luminance standard deviation across the central playfield (`30%..70%` X/Y); `initialCenterLuminanceStd < 0.75` sets `initialFrameBlank = True` (`blank_initial_canvas`). Simultaneously, `BROWSER_CANVAS_QUALITY_JS` computes pairwise bounding-box intersections (`> 4 px` overlap on both axes) across visible HUD badges, panels, and buttons (`hudOverlapCount > 0` -> `hud_layout_overlap`). Word-boundary regexes in `infer_web_profile` prevent `"window"` and `"untouched"` from activating unrequested checks, and `falsify_task` audits candidates against `build_six_angle_qa_checklist`.
