## B. Original Problem

- **Original request to Mini Hivo:** Prove empirically and architecturally on a dedicated research branch (without downloading new models or pushing to `main`) whether improving Orchestrator task decomposition enables radically weaker Worker models—specifically tiny already-installed local quantized models (`qwen2.5-coder:1.5b` at `986 MB`, `qwen2.5-coder:3b` at `1.9 GB`) and weak/legacy/low-effort cloud models (`mai-code-1.1-flash`, `gpt-5.6-luna [low]`, `gemini-3.8-flash`, `claude-haiku-5.5 [low]`)—to synthesize verified multi-module backend and Three.js 3D WebGL software.
- **Expected behavior:** Mini Hivo must (1) strictly separate Orchestrator planning/verification roles from Worker code-writing roles (`builder`, `repairer`) with zero code leakage in decomposition plans, (2) verify and repair small-worker leaf modules reliably without stochastic small-Falsifier false negatives or diff-format infinite loops, and (3) pass independent end-to-end behavioral and Playwright WebGL checks.
- **Observed behavior:** Prior to this update:
  1. Mini Hivo bound a single global `--model` to all roles, lacking asymmetric `--orchestrator-model` / `--worker-model` routing or external contract-plan injection (`--decomposition-plan`) with anti-code-leakage enforcement.
  2. Under `D0` monolithic execution, `qwen2.5-coder:1.5b`, `qwen2.5-coder:3b`, and `gemma4:e4b` scored **`0/12` (`0.0%`, `0/72` checks)** on multi-file Python tasks (`Cohort A`).
  3. Under `D2` naive oversplitting ($\kappa \approx 0.35–0.38$), both local `3B` (`0/5`) and all 4 cloud worker models (`0/12`, `0/72` checks) collapsed to **`0.0%`** due to cross-module signature/schema drift.
  4. Even with `D4` contracts (`Cohort A`), `1.5B` and `3B` workers wrote valid code (`write_file`) and stopped without re-running tests on the latest digest (`VERIFICATION_NOT_APPLICABLE`), `evidence_strict.py` rejected 4-token `python -m unittest <suite>.py` commands, `4B` LLM Falsifiers drifted or hallucinated invalid assertions, and `Repairer` looped `45x` on `edit_file_range` while `mini.py:22979` dropped `fresh_falsifier` (`None`) during failure re-classification.
- **Execution evidence:** Preserved across `98` sanitized local records in [`local_scaling_summary.json`](../evidence/asymmetric-decomposition-scaling/local_scaling_summary.json) and `37` cloud multi-file system records in [`cloud_scaling_summary.json`](../evidence/asymmetric-decomposition-scaling/cloud_scaling_summary.json).
- **Failure boundary:** First stopping boundaries prior to fix were `VERIFICATION_NOT_APPLICABLE` at `evidence_gate()` after `Builder` completion, `45`-step `edit_file_range` exhaustion inside `repair_task()`, and JSON-escaped HTML+JS syntax corruption on `<4`-module WebGL splits.
- **Reproduction before the change:** Captured in `cohort_a_baseline_39` of [`local_scaling_summary.json`](../evidence/asymmetric-decomposition-scaling/local_scaling_summary.json) (`0/12` `D0` pass, `0/5` `D2` pass, `0/10` `1.5B`/`3B` `D4` `hivo_verified` before DCVG).

## C. Why the Update Was Necessary

Without asymmetric role routing, anti-leakage contract validation, deterministic post-build/post-repair oracle execution (DCVG), and whole-file atomic leaf repair, sub-`4B` quantized local models (`986 MB`–`1.9 GB`) could not complete verified multi-file builds inside Mini Hivo even when their generated Python or ES6 code was functionally sound, and naive multi-agent splitting degraded cloud workers from `66.7%` (`100%` on `claude-haiku-5.5 [low]`) to `0.0%`.

## F. How the Fix Works

1. **Plan Ingestion & Anti-Leakage Gate:** When `--decomposition-plan` is supplied, `load_and_validate_decomposition_plan()` verifies DAG acyclicity, normalizes child IDs, validates declarative `verification_oracles`, computes $\kappa$, and scans every string/dict field via `validate_no_code_leakage()` so zero implementation lines can be smuggled from the Orchestrator into Worker packets.
2. **Asymmetric Role Dispatch & VRAM Phase Eviction:** `AsymmetricModelPolicy.model_for_role(role)` routes `builder` and `repairer` exclusively to `--worker-model` (with `num_ctx=8192` for `<=3.5B` models, schema-echo unwrapping, and single-owner fenced fallback) and routes analytical/planning roles to `--orchestrator-model`, issuing `keep_alive: 0` across phase transitions when distinct local Ollama models share a 6 GB GPU.
3. **Deterministic Component Verification Gate (DCVG) & Whole-File Atomic Repair:** After `Builder` completes a leaf, `_execute_child_verification_oracles()` executes declared `run_file`, `run_command`, `unittest`, `verify_web_app`, `expected_exports`, and `expected_source_substrings` checks against the live workspace and records fresh-digest-bound tool evidence. If all deterministic oracles pass, stochastic Falsifier LLM invocation is skipped (`0` extra LLM calls). If an oracle fails, `repair_task()` permits single-owner whole-file `write_file` (`coherent_rewrite`), re-runs DCVG immediately after repair, preserves `fresh_falsifier` in `classify_failure()`, and re-verifies all child oracles together at `ROOT` integration via `_execute_integrated_children_oracles()`.
